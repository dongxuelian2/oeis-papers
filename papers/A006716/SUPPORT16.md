# A006716: complete root-support-16 certificate with global triple-prefix pruning

**Authors:** Qichao Wang (Hebei University of Technology); Daoyu Dong (University of Electronic Science and Technology of China).
**Status:** exact finite computation supported by explicit necessary conditions. No original paper/PDF edited. Not a proof of the global finiteness of [OEIS A006716](https://oeis.org/A006716).

## New exact classification

**Theorem (finite computer-verified classification).** Let \(\nu_{10}(x)\) denote the number of nonzero decimal digits of a positive integer \(x\). If every decimal digit of \(x^2\) belongs to \(\{1,4,9\}\) and \(\nu_{10}(x)\le16\), then \(x\) is one of the 17 previously recorded square roots in [A027675](https://oeis.org/A027675). In particular, neither the support-15 nor support-16 class contains a square root of A006716.

The complete support-16 audit, partitioned by the only six possible final digits of a positive square root, gives:

| root units digit | final candidate roots | matching squares |
|---:|---:|---:|
| 1 | 44,494,558 | none |
| 2 | 27,992,500 | none |
| 3 | 24,043,075 | none |
| 7 | 98,725,329 | none |
| 8 | 46,078,292 | none |
| 9 | 26,974,857 | none |
| **Total** | **268,308,611** | **none** |

First full six-shard audit: [GitHub Actions run 39762036098](https://github.com/dongxuelian2/oeis-papers/actions/runs/39762036098) (all six jobs passed). The [source verifier](verify_sparse_roots_16.cpp) now includes pinned exact leaf counts and hard assertions that there are no matching roots, permitting an independently reproducible regression test.

Combining this with the earlier [support-14 classification](LEADING_PAIRS_AND_SUPPORT14.md) (17 roots) and the [support-15 complete exclusion](SUPPORT15_TOP_THREE.md) (zero roots), we have a complete classification through support 16 **without imposing an arbitrary numerical upper bound on the root**.

## New analytic reduction: from a two-digit to three-digit leading sieve

The [top-three-gap theorem](SUPPORT15_TOP_THREE.md) states that the highest three nonzero root positions \((e,p,q)\) can only have gaps

\[
(e-p,p-q)\in
\{(1,1),(1,2),(1,3),(2,1),(2,2),(2,3),(2,4),(3,1)\}.
\]

This follows from a global real-size argument using eight leading decimal digits of the square, and is **not** a fixed-modulus-only sieve.

For an exact three-digit leading block with digits \(a,b,c\) at positions \(e>p>q\), let \(g=e-p\), \(h=p-q\), \(D=10^{g+h}\) and \(z=aD+b10^h+c\). Then

\[
\frac{z^2}{D^2}
\le \frac{x^2}{10^{2e}}
< \frac{(z+1)^2}{D^2}.
\]

For squares with at least eight digits, this interval must intersect a prefix interval generated by an eight-digit word over \(\{1,4,9\}\). For each \(g\in\{1,2,3\}\), \(h\in\{1,2,3,4\}\), and \(a,b,c\in\{1,\dots,9\}\), the mask of feasible \((a,b,c)\) is generated *at runtime* in the C++ verifier using exact 128-bit arithmetic and only these interval inequalities. The **independent Python proof audit** [verify_top_three_gaps.py](verify_top_three_gaps.py) independently recomputes all 972 triple cases and the following mask sizes:

| g | h=1 | h=2 | h=3 | h=4 |
|---:|---:|---:|---:|---:|
| 1 | 49 | 25 | 13 | 0 |
| 2 | 49 | 12 | 5 | 5 |
| 3 | 4 | 0 | 0 | 0 |

All other high gap configurations are impossible. These *necessary* prefix conditions are used strictly at the final leading-root-digit insertion. They may also be used **one step earlier** by considering all possible final digits: if no completion can satisfy the triple-prefix table, the penultimate branch can be omitted. No actual integer square is thereby discarded.

For short squares, where eight significant digits do not exist, the independent Python audit explicitly checks the finite exceptional range \(x\le3162\); its only A006716 root with at least three nonzero digits is \(x=212\), satisfying \((g,h)=(1,1)\).

## Independent control on how far root digits may occur

The digit-sum theorem in [SPARSE_ROOTS.md](SPARSE_ROOTS.md) gives

\[
\operatorname{digits}(x^2)\le81r^2
\]

for any actual A006716 root with \(r\) nonzero digits. If its highest nonzero exponent is \(e\), then \(x^2\ge10^{2e}\), hence

\[
e \le \left\lfloor\frac{81r^2-1}{2}\right\rfloor.
\]

This provides a *proved*, non-arbitrary search-space cap in addition to the earlier low-gap bound \(e_j\le 2^j-2\). The C++ verifier uses the digit-sum exponent cap (for \(r=16\), \(e\le10367\)) to avoid manufacturing huge powers of ten that cannot belong to a genuine solution.

## Reproducibility

```sh
python papers/A006716/verify_top_three_gaps.py
g++ -std=c++17 -O3 papers/A006716/verify_sparse_roots_16.cpp -o /tmp/a006716_sparse16
for u in 1 2 3 7 8 9; do /tmp/a006716_sparse16 "$u"; done
```

The six independent jobs also run via [a006716-support16.yml](../../.github/workflows/a006716-support16.yml). The theorem is fully finite and machine-verifiable; **it is not an all-support finiteness result**. A hypothetical new member of A006716, if it exists, must have a square root with at least **17 nonzero decimal digits**. There is no claim that such a number exists.
